# Konda-From-Clang (KfC) [![CI](https://github.com/daniliammo/Konda-From-Clang/actions/workflows/ci.yml/badge.svg)](https://github.com/daniliammo/Konda-From-Clang/actions/workflows/ci.yml)

Конвертер **C → Konda** через AST-дамп компилятора **clang**. Отдельный проект,
не зависит от `libkonda` и не линкует `libclang` — общение с clang только через
внешний процесс (`clang -Xclang -ast-dump=json`).

```
файл.c ──clang -ast-dump=json──▶ JSON-AST ──kfc.py──▶ файл.конда ──▶ .c ──▶ .elf
                                              ▲            │
                                              │            ▼
                                        уточнить    транспилятор Konda
                                        политику ◀── диагностики (цикл проверки)
```

kfc **только переводит синтаксис**. Никаких проверок памяти/типов он не делает —
по инварианту экосистемы Konda все проверки безопасности живут в транспиляторе.
Поэтому результат kfc — это черновик `.конда`, который затем прогоняется через
`Транспилятор`; тот и укажет, где перевод небезопасен и требует ручной правки.

## Почему через `clang -ast-dump=json`, а не рукописный парсер

Прежний конвертер (`СиВКонда` в основном репозитории) — рукописный парсер C.
Он никогда не догонит реальный C: препроцессор, все объявители, точные типы,
разрешение имён. clang уже всё это делает и отдаёт **готовое, типизированное,
препроцессированное** дерево. Мы берём его как есть.

- **Без линковки.** clang вызывается как процесс, JSON читается из stdout.
  Обновление clang не ломает сборку (нет ABI-зависимости от libclang).
- **Верные типы.** В JSON у каждого узла есть `type.qualType` — точный тип после
  разрешения `typedef`, `sizeof`, промоушенов.
- **Препроцессор бесплатно.** `#include`, `#define`, `#if` уже раскрыты. Минус —
  раскрыты *насовсем*: исходные `#if`-ветки в вывод не попадают (см. ниже).

## Запуск

```sh
python3 kfc.py примеры/demo.c                 # печать .конда в stdout
python3 kfc.py примеры/demo.c -o out.конда    # запись в файл
python3 kfc.py а.c б.c в.c -o каталог/        # ПРОЕКТ целиком (общий граф вызовов)
python3 kfc.py compile_commands.json -o кат/  # все .c из базы компиляции
python3 kfc.py файл.c --отчёт задачи.json     # + машиночитаемый список задач
python3 kfc.py файл.c --без-проверки          # выключить цикл проверки
python3 kfc.py файл.c --итераций 10           # предел итераций цикла (по умолч. 6)
python3 kfc.py файл.c --транспилятор ПУТЬ     # где взять транспилятор Konda
python3 kfc.py файл.c --игнорировать-clang    # продолжить при ошибках clang
python3 kfc.py файл.c -- -I../include -DDEBUG # флаги после -- уходят clang'у
```

**Флаги C передаются транспилятору автоматически.** Те же `-I`/`-D`, с которыми
clang разбирал исходник (после `--` или автоподхват из `compile_commands.json`),
плюс `-I<каталог .c>` (C ищет `"x.h"` рядом с источником) kfc передаёт
транспилятору в цикле проверки (§129 транспилятора: опрос заголовков за
константами enum, переменными, типами). `-std` не передаётся (выход — gnu23),
`-U`/`-include` транспилятор не принимает. Список печатается в конце
(`флаги транспилятора: …`) и пишется в JSON-отчёт полем `флаги_транспилятора` —
собрать `.конда`: `ТранспиляторКонда <флаги> файл.конда`.

## Библиотечные C-API: «внешняя», «внешний тип», memset (GUI/wayland-паттерны)

Замер на клиентах weston показал: почти все `&x` в GUI-коде уходят в функции,
чьи сигнатуры менять НЕЛЬЗЯ (libweston/cairo/wayland). kfc закрывает это
связкой с интероп-конструкциями транспилятора:

- **`внешняя`-прототипы генерируются автоматически.** Функция вызывается с
  `&x`, но определена вне проекта (прототип или static inline в заголовке) →
  kfc объявляет `внешняя ничего widget_get_allocation(widget* ш, изменяемый
  rectangle р)` (const T* → `чтение`), снимает `&` на вызовах (его поставит
  кодоген транспилятора). Позиция становится ссылкой, если ВСЕ вызовы дают
  `&lvalue`; неконвертируемая позиция больше не отменяет функцию целиком —
  остаётся сырым указателем, а остальные позиции выигрывают.
- **`внешняя`-прототип также при возврате opaque-указателя.** Даже без `&`-
  параметров: если внешняя функция ВОЗВРАЩАЕТ указатель на пользовательский/
  opaque-тип (`opendir` → `DIR*`, `readdir` → `dirent*`), kfc эмитит
  `внешняя DIR* opendir(символ* …)`. Без этого транспилятору неизвестен тип
  результата, и присваивание `возможно<DIR*> d = opendir(…)` не проходит
  проверку типов. Пример: `примеры/внешний_возврат.c`. (Доступ к ПОЛЯМ
  системной структуры — напр. `entry->d_name` у `dirent` — отдельный барьер:
  нужен транспиляторный «внешний тип с полями», см. ниже.)
- **`&lvalue` — не только переменная, но и ПРОЕКЦИЯ**: `&s.f`, `&s->a.b`,
  `&arr[i]` (цепочки полей/индексов с корнем-переменной; индексация только
  массива C — сырой указатель в Konda за `небезопасно`). Транспилятор принимает
  такие аргументы в `изменяемый`/`вывод`/`чтение` (second-class reference,
  границы среза — при формировании ссылки).
- **`void *data`- и `T**`-позиции типизируются по аргументам.** Общее правило:
  если ВСЕ вызовы дают `&lvalue`, тип ссылки берётся из того, на что указывает
  `&`, а C-декларация из заголовка не меняется (кодоген транспилятора сам снимет
  `&`).
  - **`void *data`** (главный GUI-паттерн: `wl_*_add_listener(объект,
    &слушатель, &данные)`): единый тип `T` аргументов (не char/void/указатель) →
    `изменяемый T`. Конверсия `T*`→`void*` легальна; BitCast вокруг снятого `&`
    реинтерпретацией не считается (исчезает вместе с `&`).
  - **`T**` — out-указатель** (`weston_config_section_get_string(…, &str, …)`,
    `get(&ptr)`): аргумент `&x` типа `T*` → параметр `изменяемый T*` (для
    `char**` — `изменяемый символ*`). В библиотеку уходит тот же `T**`.
  - Байтовые libc (`memset`/`memcpy`/…) исключены — их `void*` не типизируется в
    принципе (размер задаёт третий аргумент), а у `memset` свой путь (полевое
    обнуление).
- **Колбэк-регистрация** (`glutDisplayFunc(display)`, `wl_*_add_listener`):
  аргумент — голое имя функции проекта, а параметр — указатель на функцию.
  kfc порождает `внешняя ничего glutDisplayFunc(glutDisplayFunc_callback ф)` с
  параметром-`типфункции`: именованный C-typedef колбэка (`Обработчик`)
  используется по имени, анонимный `void (*)(int)` → синтез
  `Функция_параметр`. Транспилятор принимает имя функции в такой параметр
  (сверка сигнатуры статическая).
- **`#include` переносятся из исходника** (не синтезируются) — путь
  сохраняется (`<GL/glut.h>`, не `<glut.h>`); из них C берёт декларации
  `внешняя`-функций (сам транспилятор их прототип не печатает). Локальный
  заголовок, чью СТРУКТУРУ kfc переэмитит (`мф_счёт.h` → `структура Счёт`), не
  включается — иначе анонимный C-typedef структуры столкнётся с нашим;
  fnptr-typedef (`Обработчик`) переопределяется идентично и включению не мешает.
- **Точка входа `main(argc, argv)` (§36).** Сигнатура транспилятора ЕДИНА —
  `целое32 точка_входа(срез<символ*> аргументы)`. kfc отображает: `argv` →
  `аргументы` (срез, `argv[i]` → `аргументы[i]`), `argc` → `длина(аргументы)`.
  `int main(void)` тоже получает `срез<символ*> аргументы`. NB: `argc` теперь
  производное значение, а не мутируемая переменная — код с `&argc`/`argc--` не
  переводится напрямую (нужна локаль-копия).
- **Циклы `для` — без обрамляющих скобок (§38).** `for(init; cond; inc)` →
  `для init; cond; inc {` (старая форма `для (…)` снята из транспилятора).
  `если (…)`/`пока (…)` со скобками ещё валидны и не тронуты.
- **Заголовки переносятся ВСЕ (`#содержит`), типы из них не переписываются
  родными.** Транспилятор сам читает C-заголовки (его §127/§130/§131), поэтому:
  - **перечисления заголовков не переносятся** — тип `xdg_toplevel_resize_edge`
    и константы транспилятор берёт из C (варианты, исчерпываемость `выбор`);
  - **структуры заголовков** (замыкание by-value, локальные заголовки проекта)
    печатаются `внешний тип X { поля }` — в C не печатаются, конфликта с
    заголовком нет; поля не переименовываются (в C у них исходные имена);
  - **непрозрачные хендлы из заголовков** (`wl_surface`, `cairo_t`) не
    объявляются вовсе — транспилятор выводит `внешний тип` сам; `внешний тип
    Имя` печатается лишь для типов, объявленных в самом `.c`;
  - так `#include` локальных/сгенерированных заголовков (протоколы wayland
    `xdg-shell-client-protocol.h`, `shared/*.h`) больше не выпадает — их
    `static inline`-функции и `extern`-переменные видны C и транспилятору.
- **Указатель-алиас `T *p = &LVAL` → подстановка lvalue (без `&`).** Самый частый
  «адрес-оф»: `struct buffer *b = &d->buffers[i]; b->busy = 1; mark(b);`. Если
  `p` присвоен один раз (объявлением или оператором `p = &LVAL;` — тогда все
  ссылки на `p` должны идти после него в том же блоке), а части LVAL (база,
  индексы, члены пути) в области `p` не меняются, kfc подставляет само lvalue:
  `p->поле` → `d.buffers[i].поле`, `*p` → `d.buffers[i]`, `f(p)` → `f(&LVAL)` →
  параметр `изменяемый` (ссылка на проекцию). Иное использование `p`
  (сравнение, сохранение, возврат) — откат в прежнюю пометку адрес-оф.
- **Замыкание типов.** Поле локальной структуры или `изменяемый`-позиция
  внешнего прототипа ссылается на тип из заголовка by-value (`wl_list`,
  `rectangle`) → `внешний тип X { поля }` добавляется в перевод (рекурсивно).
- **`memset(&s, 0, sizeof(s))` → полевое обнуление** (вложенные структуры —
  рекурсивно, массивы — циклом) — `&` исчезает вовсе. Отказ при поле-указателе
  (нулевой указатель — только «возможно», молча нулить нельзя).
- **Поле-указатель-на-функцию без typedef** (`void (*run)(...)`) больше не
  деградирует в `символ**`: синтезируется `типфункции Структура_поле(…)`.
- **Локаль-указатель на функцию** (`int (*op)(int,int) = add`): пред-проход по
  телам синтезирует `типфункции RET ФнптрN(типы)` на верхнем уровне (дедуп по
  сигнатуре), локаль эмитится как `ФнптрN op = add` — присваивание/вызов/
  переприсваивание работают штатно.
- **Ошибки clang больше не глотаются.** Fatal (не найден заголовок) → отказ с
  перечнем и подсказкой про `-- -Iпуть -DФЛАГ`; перевод из неполного AST был бы
  молча неверен. Осознанно продолжить — `--игнорировать-clang`.

Результат на weston/clients (7 файлов): класс «адрес-оф» упал с 59 до 14;
calibrator.c на полном AST — 13 → 7 задач (блокирующих 9 → 3). Эталоны —
`примеры/библио.c` («&x» в библиотеку + memset) и `примеры/графика.c` (OpenGL/
GLUT: `argc`, колбэк `glutDisplayFunc`, `<GL/glut.h>`) — 0 пометок, работают
(GLUT-программа компилируется и линкуется; `-lglut` пока указывается вручную —
транспилятор не пробрасывает `-l` для системных библиотек).

## Многофайловый проект

Несколько `.c` (или `compile_commands.json` — из него берутся файлы и их
`-I`/`-D`/`-std`) конвертируются КАК ОДИН ПРОЕКТ:

- **Общий граф вызовов.** Анализы владения и nullable считаются по всем файлам
  сразу: функция из `дин_массив.c`, вызываемая с `&x` из `лексер.c`, получает
  `изменяемый` так же, как внутри одного файла. При пофайловой конвертации это
  была бы «чужая сигнатура» — главный источник пометок на реальном коде.
- **Типы из заголовков проекта.** Структуры/enum/typedef из НЕсистемных `.h`
  (заголовки самого проекта) эмитятся в `.конда` — ровно один раз на проект,
  даже если заголовок включён из нескольких файлов. Идиома
  `typedef struct {…} Имя;` распознаётся (имя typedef переносится на тег).
  Системные (`/usr/…`) не трогаются — их типы приходят через `#содержит`.
- **Совместная проверка.** Цикл проверки гоняет транспилятор по конкатенации
  всех `.конда` (семантически то же, что `Транспилятор а.конда б.конда`, но
  строки диагностик однозначно маппятся обратно в свои файлы); проект без
  `main` проверяется с `--библиотека`. Результат компилируется как
  `Транспилятор файл1.конда файл2.конда …` — без заголовков между файлами.
- Одноимённые `static`-функции из разных файлов не переписываются (граф по
  имени их не различает) — консервативно остаются как есть.

Требуется `clang` в `PATH` и `python3` (только стандартная библиотека). Для цикла
проверки нужен бинарник транспилятора Konda: ищется по `--транспилятор`, затем
`$KONDA_ТРАНСПИЛЯТОР`, затем у соседа `../ТранспиляторКонда/Собранное/Транспилятор`,
затем в `PATH`. Без него цикл молча выключается (перевод остаётся эвристическим).

## Цикл проверки: «сгенерировал → проверил транспилятором → уточнил»

kfc не угадывает, где нужна небезопасность, — он **спрашивает транспилятор**.
Тот собирает семантические ошибки ПАЧКОЙ за прогон, поэтому цикл сходится за
2-3 итерации. Транспилятор запускается ПОДПРОЦЕССОМ (libkonda не линкуется —
по инварианту экосистемы; узкое место всё равно clang, а не запуск процесса).

Лестница ослабления для каждого места — ослабляем строго по факту возражения:

| шаг | что делаем | когда |
|---|---|---|
| 1 | безопасный перевод (`срез`/массив) | по умолчанию |
| 2 | параметр `T*` → **`изменяемый`/`вывод`** | «выходной параметр не присвоен» → ref; «изменяемый-аргумент не инициализирован» → out |
| 2 | параметр `T*` → **`срез<T>`** | «…теряет длину: объявите как срез<T>» |
| 3 | `небезопасно { оператор }` | «индексация сырого указателя», «арифметика указателей», reinterpret, доступ к союзу |
| 4 | `небезопасно { }` на всё тело функции | переменная ушла из области («неизвестная переменная») |
| 5 | пометка `KONDA-TODO` | ничего из перечисленного не помогло |

Пример выигрыша (`примеры/цикл_проверки.c`): у функции `обёртка` параметр не
индексируется в теле, поэтому статическая эвристика оставляет сырой указатель —
и такой код транспилятор бы отверг. Цикл видит ошибку на вызове и сам поднимает
параметр до `срез<целое32>`:

```
--без-проверки → целое32 обёртка(целое32* a, целое32 n)      // отвергается
с циклом       → целое32 обёртка(срез<целое32> a, целое32 n) // принят, 0 пометок
```

В конце kfc печатает вердикт: `итог: принят транспилятором (итераций цикла: 2);
пометок: 0` — то есть перевод **доказанно** проходит транспилятор, а не «наверное».

## Эвристика владения: `f(&x)` → `изменяемый` / `вывод`

В Konda нет оператора `&` — мутация переменной вызывающего выражается
**модификатором параметра**, а `&`/`*` расставляет кодоген. Раньше каждый
`f(&x)` был блокирующей пометкой; теперь `владение.py` выводит это сам.

Для каждой функции, **определённой в файле**, смотрим на её указательные
параметры и на все вызовы в файле:

| в теле функции | все вызовы дают `&переменная`? | результат |
|---|---|---|
| только пишет `*p = …` | да | **`вывод T p`** (C# out) |
| читает и/или пишет `*p`, `p[0]`, `p->поле` | да | **`изменяемый T p`** (C# ref) |
| **пересылает `p` в функцию, чей параметр стал ссылкой** | да | режим приёмника (транзитивность) |
| индексирует `p[i]`, i≠0 | — | `срез<T>` (другой путь) |
| арифметика `p+n`, `p++`, переприсваивание, `вернуть p`, `&p` | — | сырой указатель |
| передаёт `p` во внешнюю/неизвестную функцию | — | не трогаем (чужая сигнатура) |
| хоть один вызов даёт не `&переменная` и не параметр-ссылку | нет | не трогаем |

**Транзитивность (фикспоинт).** Пересылка `g(p)` внутри `f` не блокирует
перевод: если параметр-приёмник `g` становится ссылкой, легальна и вся цепочка
(в Konda проброс `изменяемый` → `изменяемый` штатен, кодоген всё расставит).
Условия «вызовы дают `&lvalue` ЛИБО параметр-ссылку вызывающего» и «пересылки
ведут в ссылки» взаимно рекурсивны → решаются наибольшей неподвижной точкой:
оптимистично включаем всех кандидатов и вычёркиваем нарушителей до
стабилизации. Режим пересылочного параметра выводится из приёмников (все
`вывод` → `вывод`, иначе `изменяемый`); цикл пересылок без единого прямого
чтения/записи остаётся указателем. Пример — `примеры/транзит.c`: цепочка
`&х → шагнуть → прибавить` переводится целиком, 0 пометок. На реальном коде
(`токенизатор_лексер.c` транспилятора) это сняло 21 из 40 блокирующих пометок,
а вместе с многофайловостью — ещё ~15.

В теле `*p`/`p[0]` печатаются просто как `p`, на вызове `&x` → `x`. Внешние
функции (`scanf` и пр.) не трогаем — их сигнатуру менять нельзя.

Догадку «вывод vs изменяемый» **проверяет и правит цикл**: транспилятор точно
скажет `выходной параметр «p» не присвоен до возврата` (→ переключаем на
`изменяемый`) или `«изменяемый»-аргумент «x» должен быть инициализирован`
(→ пробуем `вывод`); если не подошло ни то, ни другое — откат к указателю.

## NULL-указатели → `возможно<T*>` (`нулевые.py`)

В Konda обычный `T*` ненулевой по умолчанию: `= нуль` и объявление без
инициализатора — ошибки. C этого различия не знает. kfc находит указатели,
которые реально бывают NULL, и переводит их в `возможно<T*>`:

- **Свидетельства** (фикспоинт по графу вызовов): присваивание/инициализация
  NULL; `вернуть NULL` (→ `возможно<T*>`-возврат функции); получение значения
  от nullable-функции; сравнение с NULL или проверка истинности (`if (p)`,
  `!p`, `p && …`) — clang в режиме C не ставит `PointerToBoolean`, поэтому
  булев контекст распознаётся по ТИПУ операнда.
- **Эмиссия**: NULL → `нуль` (включая `(void*)0`; его имплицитный BitCast не
  путается с reinterpret); `if (p)` → `если (п != нуль)`, `if (!p)` →
  `если (п == нуль)` — ровно формы, под которыми транспилятор сужает
  nullable; `T *p;` без инициализатора → `возможно<T*> p = нуль`.
- **Мёртвые проверки**: срез (из `выделить`) и параметр-ссылка нулевыми не
  бывают — их NULL-проверки сворачиваются в константу (`если (ложь)`), OOM
  после malloc в Konda не выразим и не нужен.
- **Свидетельства делятся на сильные и слабые**: сильное (NULL присваивается/
  возвращается) отменить нельзя — без `возможно` код не скомпилируется; слабое
  (только сравнение) цикл проверки может отменить, если `возможно` породило
  новые ошибки, и наоборот — включить nullable по диагностике «указатель
  ненулевой по умолчанию …».

- **Nullability-атрибуты clang** (`_Nullable`/`_Nonnull`/`_Null_unspecified`) —
  ПРЯМОЕ свидетельство из исходника, надёжнее вывода: `_Nullable` → сильное
  «бывает NULL» (→ `возможно<T*>`), `_Nonnull` → «точно не NULL» (гасит любой
  вывод nullable, даже сравнение с NULL). Атрибут возврата (до списка параметров
  в `qualType`) задаёт nullability возврата функции. Из имени типа атрибуты
  убираются (иначе `_Nullable` утёк бы в вывод как «int _Nullable»).
- **Nullable побеждает ссылку**: nullable-указатель НЕ становится
  `изменяемый`/`вывод` (те ненулевые по определению) — идёт путём `возможно<T*>`.
  NULL-анализ считается ДО эвристики владения и передаётся в неё.

Пример — `примеры/нулевой.c`: функция «нашлось/NULL» + охранники, 0 пометок,
0 `небезопасно`; `примеры/аннотации.c`: `_Nullable`→`возможно<T*>`,
`_Nonnull`→ненулевая ссылка.

### Конвенции освобождения: `*_free`/`*_destroy` → снять (autofree)

Знания «кто владеет памятью» в типах C нет — но оно часто закодировано в ИМЕНАХ:
kfc распознаёт освобождающие функции по конвенции и снимает их вызов на
владеющем `срез<T>`/`буфер<T>`/`Ящик<T>` (память освобождает autofree):
- **чистые free-алиасы** (`free`, `g_free`, `xfree`, `kfree`, `vfree`) — снимаются
  молча;
- **деструкторы** (`*_free`, `*_destroy`, `*_delete`, `*_dispose`) — снимаются, но с
  пометкой `ПРОВЕРИТЬ`: если функция делала БОЛЬШЕ, чем `free` (закрыть fd, снять
  с учёта), эти действия надо вернуть вручную (или оформить `[удалить = …]`).
- **Рефкаунт** (`*_unref`/`*_release`) НЕ снимается — освобождает лишь при счётчике
  0, снятие было бы неверным.

Двойное освобождение через любую из этих функций (в т.ч. `free` + `foo_free` на
одной переменной) ловится как `ПРОВЕРИТЬ` (double-free в исходном C).
Пример — `примеры/освобождение.c`.

### Локальный указатель-алиас: `T *p = &x;` → подстановка

Локальный указатель на переменную — это просто **другое имя** для неё. kfc
подставляет `x` вместо `p` и вовсе опускает объявление (`примеры/локальный_указатель.c`):

```c
int x = 5;  int *p = &x;      →   целое32 x = 5
printf("%d", p[0]);  *p = 10; →   printf("%d", x)   x = 10
Точка *ук = &т; ук->x += 100; →   т.x = т.x + 100
```

Условие безопасности: **каждое** упоминание `p` — разыменование (`*p`, `p[0]`,
`p->поле`). Любое другое использование (переприсваивание `p = …`, арифметика
`p + 1`, передача `f(p)`, `вернуть p`) значит, что указатель живёт своей жизнью —
тогда не подставляем. Цели с индексом (`&массив[и]`) тоже исключены: `и` мог бы
измениться между объявлением и использованием, и подстановка изменила бы смысл.

Результат (`примеры/владение.c`) — пять типовых C-паттернов мутации переводятся
**полностью автоматически, 0 пометок**, и вывод совпадает с оригинальным C:

```c
void заполнить(int *р)      { *р = 42; }        →  ничего заполнить(вывод целое32 р)
void удвоить(int *з)        { *з = *з * 2; }    →  ничего удвоить(изменяемый целое32 з)
void сдвинуть(Точка *т,…)   { т->x = …; }       →  ничего сдвинуть(изменяемый Точка т, …)
заполнить(&r); удвоить(&v); сдвинуть(&т, 10);   →  заполнить(r) удвоить(v) сдвинуть(т, 10)
```

## Стратегия безопасности: минимум «небезопасно», честные пометки

Цель — чтобы вывод **прошёл транспилятор и работал как задумано**. Правила
(выведены эмпирически из транспилятора):

- **Массив/срез индексируются безопасно** (проверка границ) — `небезопасно` не
  нужно. **Сырой указатель** (индекс `p[i]`, разыменование `*p`, арифметика
  `p + n`, reinterpret-cast `(T*)x`, доступ к члену `union`) требует
  `небезопасно { }` — kfc оборачивает **минимально**, только задетые операторы.
- **Указательный параметр `T*`, который в теле индексируется** и не участвует в
  арифметике, переводится в **`срез<T>`** — тогда индексация внутри безопасна, а
  длина сохраняется. Массив на вызове передаётся в такой параметр напрямую.
- **Типизированные слушатели (C-идиома listener → три конструкции Konda).**
  Распознаёт `X_add_listener(obj, &G, data)`, где `G` — глобал-структура-таблица
  колбэков, а колбэки кастуют `void*→T` (`struct T *x = data`), и переписывает в
  `внешний слушатель<T> S_сл для S { … }` + экземпляр `S_сл G = { поле = функция }`
  + `слушать(X_add_listener, obj, G, data)`. Тела колбэков переписываются: первый
  параметр `void*data` → `изменяемый T x` (каст и `struct T *x = data` убираются,
  `x` — теперь сам параметр), тело перестаёт быть `небезопасно`. Каст `void*→T`
  уходит в сгенерированный транспилятором трампулин. **Гейт безопасности:**
  распознаём только слушателей, чья C-структура `S` приходит из СИСТЕМНОГО
  заголовка (`#содержит`) — тогда трампулин печатает валидный `struct S`. Если
  kfc сам переэмитит `S` как Konda-typedef (локальный заголовок), идиома
  пропускается (иначе `struct S`-литерал конфликтовал бы с typedef) — остаётся
  сырой путь. Полная активация на любых заголовках требует отдельной правки
  переэмиссии структур (tagged-struct vs typedef). **Гейт фазы 2 (владение
  `данные`):** транспилятор (§68) требует, чтобы `данные` слушателя были
  `Ящик<T>` (владеющий heap-объект — иначе колбэк получит висячий указатель после
  возврата). Поэтому идиома распознаётся только когда `data` — переменная-указатель
  (её выделили `malloc`/`xzalloc` → kfc даёт `Ящик<T>`); адрес стека `&x` под это
  не подходит → сырой fallback (вывод kfc всегда компилируется транспилятором).
- **`malloc`/`calloc` → `срез<T> p = выделить(N)`**, последующие `p[i]` безопасны,
  а `free(p)` **отбрасывается** (у среза автоосвобождение). Число элементов
  извлекается из `N*sizeof(T)` / `calloc(N,…)`; если неоднозначно — пометка.
  **Элемент `T` теперь может быть структурой или указателем** (`срез<Точка>`,
  `срез<символ*>`, `срез<Виджет*>`) — транспилятор Konda принимает типы элемента
  среза, поэтому массивы структур и массивы строк/указателей переводятся так же,
  как массивы примитивов (а не запираются в `небезопасно`). **С §61 языка
  элемент-структура может ВЛАДЕТЬ ресурсом** (поле-указатель на heap / свой
  `[удалить]`): `срез<Структура>` и `Структура имя[N]` больше не отвергаются —
  транспилятор эмитит поэлементную деструкцию. То есть таблицы владеющих записей
  (`struct Rec { char *name; … } recs[N]`) переводятся в `срез`/массив, а не в
  сырой указатель под `небезопасно` (когда `&`/адрес-оф не мешает выше). Обёртки-аллокаторы
  **`zalloc`/`xzalloc`/`xmalloc`/`xcalloc`** (частые в weston) распознаются как
  malloc-семейство, но **только для массивных форм** (`n*sizeof`/`calloc(n,…)`):
  их одиночная форма `alloc(sizeof(T))` — владеющий одиночный объект, его цель
  `Ящик<T>` (ещё не реализован), а `срез<T>` длины 1 сломал бы доступ `.поле`.
  Если ту же переменную-срез освобождают **повторно** в одной функции — в
  исходном C это **double-free (UB)**. Перевод от этого не страдает (лишний
  `free` снят, autofree освобождает ровно раз), но kfc помечает место как
  `ПРОВЕРИТЬ` — исходная логика содержала баг; пример — `примеры/двойной_free.c`.
- **Растущий буфер: `realloc` → `перевыделить`, указатель → `буфер<T>`.** Если
  локальный указатель где-то в функции **реаллоцируется** (`p = realloc(p, …)` —
  пред-скан находит это до эмиссии), он объявляется не `срез<T>`, а **`буфер<T>`**
  (растущий владеющий буфер, §59 языка): `malloc(N*sizeof(T))` → `выделить(N)`,
  `p = realloc(p, M*sizeof(T))` → `перевыделить(p, M)`, `free(p)` снимается
  (autofree). Индексация `p[i]` — с проверкой границ, как у среза. Пустой старт
  `T* p = NULL` (частая идиома перед первым `realloc`) → `буфер<T> p = выделить(0)`.
  Пример — `примеры/буфер_realloc.c`. **v1:** цель `realloc` — простой локальный
  указатель; поле структуры (`s->buf = realloc(s->buf, …)`) и обёртки (`xrealloc`)
  пока остаются в `небезопасно` (буфер как поле структуры язык ещё не выражает).
- Если сырой указатель **объявляется с небезопасным инициализатором** (арифметика/
  reinterpret) и живёт дальше по коду, statement-обёртка невозможна (переменная
  ушла бы из области) — тогда **тело функции целиком** оборачивается в
  `небезопасно { }` (+ пометка, чтобы позже сузить/перевести в `срез`).
- Избыточное `небезопасно` безвредно (обычный C-блок, нулевая цена) — поэтому в
  спорных местах kfc оборачивает консервативно, гарантируя проход.

## Что уже переводится

- Функции, параметры, тело; `main` → `точка_входа` (соглашение языка).
- **Типы**: примитивы C → Konda (`int`→`целое32`, `char`→`символ`,
  `double`→`вещественное64`, `unsigned` → префикс `неподписанный`, `void*` →
  `символ*`), указатели суффиксом `*`; **`struct`/`union`/`enum`** →
  `структура`/`союз`/`перечисление`; typedef указателя на функцию → `типфункции`.
  **Анонимный `enum {…}`** (у Konda-перечисления обязано быть имя) → глобальные
  `конст целое32 ИМЯ = знач` (явные значения как есть, авто — счётчик).
  **Локальный enum** (в теле функции) выносится на верхний уровень.
  **`_Static_assert`** снимается молча (проверка времени компиляции C — аналога
  и рантайм-эффекта нет).
- **Операторы**: `если/иначе` (цепочки как вложенные `иначе { если … }`), `пока`,
  `для`, `do-while` → `пока (истина){…}`. **Konda не имеет унарного `!`**, поэтому
  «выйти, если не условие» кодируется без отрицания: `если (усл) {тело} иначе
  {прервать}` (для `do-while` — пустой then). `вернуть`, `прервать`, `продолжить`.
- **Присваивание в условии цикла** (`while ((x = f()) != NULL)`, `n = read(...) > 0`,
  и т.п.): в Konda присваивание — оператор, не выражение, поэтому конвертер
  **выносит его в тело**: `пока (истина) { x = f(); если (x != нуль) {тело} иначе
  {прервать} }`. Поддержаны `while`/`do-while`/`for` и несколько/вложенных
  присваиваний (в порядке вычисления). **Отказ (пометка `ОШИБКА`)** только когда
  безусловный вынос сломал бы семантику: присваивание за `&&`/`||`/`?:` (короткое
  замыкание) или в `for` с `continue` (пропустился бы шаг) — такие переписываются
  вручную. **`switch` → цепочка `если/иначе если`** (Konda-`выбор`
  только для enum/sum-типов; `case A: case B:` → `x == A или x == B`; `break`
  отбрасывается; состекованные метки, в т.ч. `default: case X:`, разворачиваются
  полностью). Провал (fallthrough) помечается **только настоящий**: терминатором
  ветки считается не только `break`/`return`, но и диверджентный вызов
  (`exit`/`abort`/…), поэтому `case X: …; exit(1);` провалом не считается.
- **Выражения**: бинарные (`&&`/`||` → `и`/`или`), присваивания, вызовы,
  индексация, поле `.`/`->` → `.`, каст → `как<T>(…)`, `sizeof` →
  `размер_обьекта(…)`. Строки с кириллицей раскодируются из октальных escape'ов
  в UTF-8. `printf` — как есть. **Явные скобки СОХРАНЯЮТСЯ** (Konda — тот же
  C-приоритет; `(a+b)/c` не должно стать `a+b/c`). **Целые float-литералы**
  `2.0`/`100.0` (clang роняет `.0`) восстанавливаются с точкой — иначе
  `(a+b)/2.0` было бы целочисленным делением.
- **`char s[N] = "…"`** → литерал массива символов `{ 'h', 'i', '\0' }`
  (транспилятор требует литерал; хвост C зануляет; размер `char s[]="hi"` —
  длина+NUL). Escape/не-ASCII байты — через октальный char-литерал.
- **Унарное `!`** (в Konda его нет): `!указатель` → `указатель == нуль`;
  `!(сравнение/логика)` → `(… == ложь)`; `!целое` → `(целое == 0)`.
- **Операторы-выражения — НАТИВНЫЕ формы транспилятора** (не разворот): составное
  присваивание `+= -= *= … <<=` → `x += y` (§45), постфикс `x++`/`x--` → `x++`
  (§47). Так цель эмитится ОДИН раз (разворот `x = x + y` при побочке в цели —
  напр. `arr[i++]` — сработал бы дважды), узкие типы (`символ`, `целое8`) не
  расширяются, и работают guard'ы/перегрузка операторов транспилятора.
- **`++`/`--` ВНУТРИ выражения** (в Konda инкремент — только оператор): побочка
  выносится строкой рядом с оператором. Префикс `++x` — строкой ПЕРЕД,
  постфикс в простом операторе — ПОСЛЕ (`*p++ = v` → `p[0] = v` + `p++`,
  `a[i++] = x` → `a[i] = x` + `i++`), постфикс в условии `if`/`return` — через
  temp со старым значением; `while (n--)`/`while (*s++)` → `пока (истина) {
  вынос; если (усл) {тело} иначе {прервать} }` (как в C, включая `continue`).
  Нельзя вынести (правый операнд `&&`/`||`, заголовок `for`, операнд с вызовом) —
  пометка `инкремент-в-выражении`. Пример — `инкремент_выражение.c`.
- **Тернарник `?:`** понижается в `если/иначе` (нет тернарника-выражения в Konda):
  в объявлении (`T x = c ? a : b`), `return` и присваивании (`x = c ? a : b` →
  `если (c) { x = a } иначе { x = b }`). **Вложенный** тернарник (`c1 ? (c2?a:b) : d`)
  разворачивается РЕКУРСИВНО — во всех трёх позициях. **Тернарник в ПРОИЗВОЛЬНОЙ
  под-позиции** (операнд бинопа `a + (c?b:d)`, аргумент вызова `f(c?a:b)`, индекс
  `arr[c?i:j]`) больше не остаётся пометкой: kfc **хостит** его — заводит temp,
  печатает `если/иначе` строкой ВЫШЕ оператора и подставляет имя temp на место
  `?:` (temp объявляется без инициализатора — обе ветви присваивают, чего
  definite-assignment транспилятора достаточно, и это верно даже для ненулевого
  указателя). **Исключение — заголовок цикла** (`for (…; c?a:b; …)`, `while (c?a:b)`):
  там условие вычисляется КАЖДУЮ итерацию, а вынос temp ПЕРЕД циклом сломал бы
  семантику → остаётся пометкой. Замер: 40 файлов weston/clients — 0 крашей,
  0 оставшихся тернарник-пометок в под-позиции.
- **C89-объявления указателей** (`T *p;` в начале функции, `p = выр;` позже —
  в т.ч. в цикле): ненулевой указатель без инициализатора Konda не принимает,
  поэтому kfc опускает объявление к первому присваиванию (`T* p = выр`), если
  все упоминания `p` лежат в том же блоке после него. Небезопасный
  инициализатор указателя — выражение-форма `T* p = небезопасно(выр)` (блок
  `небезопасно { T* p = … }` ограничил бы область объявления).
- **Указатель в середину среза** (`p = данные + k`, где `данные` уже срез) →
  подсрез `срез<T> p = данные[k:]` (§42, границы проверяются) — индексация `p`
  безопасна, `небезопасно` не нужно. Пример — `объявление_c89.c`.
- **Глобалы**: структура без C-`const`, чей адрес уходит только в
  `const T *` (слушатели wayland: `wl_*_add_listener(o, &слушатель, d)`), —
  `конст`; предварительное объявление при определении ниже печатается один раз;
  глобал, чей адрес лежит в таблице опций (`{ …, &opt_x }` — C пишет через
  указатель), — пометка `изменяемый-глобал` (не ложный `атом`). Пример —
  `глобалы.c`.
- **Арифметика символа** (`c - '0'`, `(char)(c - 32)`): C неявно повышает
  `char` до `int`, а Konda требует ЯВНОЙ конверсии (§75 — без `небезопасно`).
  kfc оборачивает повышенный операнд-символ и символьный литерал в арифметике в
  `код(…)`: `код(c) - код('0')`, `как<символ>(код(c) - 32)`; сравнения
  (`c >= 'a'`) — как есть. Пример — `символ_код.c`.
- **Имя функции** `__func__`/`__FUNCTION__`/`__PRETTY_FUNCTION__` (clang
  `PredefinedExpr`) → встроенная **`имя_функции()`** (§118 языка): имя объемлющей
  функции, проверенное компилятором, 0 рантайма. Исключение — `main`: он
  становится `точка_входа`, и `имя_функции()` дало бы другой текст, поэтому там
  остаётся исходный литерал `"main"` (вывод совпадает с C). Аналог C#-`nameof`
  (`имя_от(…)`) в C не имеет AST-следа (`#x` в макросе clang отдаёт готовым
  строковым литералом) — в него kfc не переводит. Пример — `имя_функции.c`.
- **`assert(усл)`** (glibc раскрывает его в statement-expression с
  `__assert_fail`) → встроенная **`утверждать(усл)`** (§120 языка): проверка и в
  релизе, при провале — текст условия, строка и функция. При `NDEBUG` — ничего.
- **`sizeof(выражение)`** → `размер_обьекта(ТИП)` (тип берётся у clang;
  транспилятор принимает только тип), `sizeof(массив)` →
  `размер_обьекта(T) * N`.
- **Типы из заголовков.** typedef скаляра/перечисления системного заголовка
  (`GLint`, `time_t`, `VkStructureType`) → примитив Konda; typedef-хендл
  (`typedef struct X_T *VkDevice`) → `X_T*` + `внешний тип X_T`; typedef-
  псевдоним ПОЛНОЙ записи (`cairo_matrix_t` → `_cairo_matrix`, цепочки
  `sigset_t` → `__sigset_t`) → сама запись; typedef указателя на функцию из
  заголовка (`__sighandler_t`) → `типфункции`. Записи заголовков, нужные по
  значению (поля, локали, параметры, возвраты), добавляются замыканием типов.
- **Двумерный массив** `T a[N][M]` → нативный 2D-массив Konda (§55); три и
  больше измерений — пометка `многомерный-массив`.
- **Интрузивные списки wayland** (§121 языка): `wl_container_of`/`container_of`
  (`(T*)((char*)p - offsetof(T, поле))`) → `контейнер_из<T>(p, поле)`;
  раскрытый `wl_list_for_each[_reverse][_safe]` → `для_каждого э из
  интрузивный<T>(голова, поле[, обратно][, с_удалением])` под `небезопасно`
  (целостность C-списка язык не доказывает). Пример — `интрузивный_список.c`.
- **`goto` — выход из вложенных циклов** (§122 языка): `goto L`, где `L:` стоит
  сразу за циклом → `L: для …` + `прервать L`; пустая `L: ;` последней в теле
  `for`/`while` → `продолжить L`. Пример — `метки_циклов.c`.
- **`memcpy(D, S, sizeof(T))`** объектов одного типа → присваивание объекта
  `*D = *S` (без `&` и байтов). Байтовые копии буферов — как есть. Пример —
  `memcpy_объект.c`.
- **Вещественные литералы**: значения с экспонентой — как есть (§119 языка);
  объектный макрос, раскрывающийся ровно в один вещественный литерал (`DBL_MAX`,
  `M_PI`), — ИМЕНЕМ (таблица `clang -dM -E`); макрос-выражение и функциональный
  макрос раскрываются. Пример — `вещественные_литералы.c`.
- **Поле с именем типа** (`struct window { struct display *display; }`: в C
  теги и члены — разные пространства имён, в Konda — одно) → `display_` в
  определении, доступе и инициализаторах. Пример — `поле_имя_типа.c`.
- **Прототипы библиотек `внешняя`** печатаются ТОЛЬКО там, где без них нельзя:
  позиция принимает `&x` (режим `изменяемый`/`чтение`), колбэк (`типфункции`) или
  возврат — указатель на пользовательский тип. Прочие функции заголовков
  транспилятор знает сам (§115/§117), дубли не нужны.
- **Вставка ассемблера** `__asm__`/`asm` → **`асм(…)` в `небезопасно`** (§60
  языка). Синтаксис секций Konda-`асм` (`"шаблон" : выходы : входы : порча`)
  1:1 совпадает с расширенным asm C, поэтому `(…)`-часть берётся ДОСЛОВНО из
  исходника (clang в JSON-AST **не** сериализует шаблон/ограничения/порчу —
  только операнды-выражения; текст надёжнее). Всегда оборачивается в
  `небезопасно { }` (ассемблер — сырой доступ). Слитные пустые секции C
  (`"" ::: "memory"`) разносятся (лексер Konda склеил бы `::`). Пример —
  `примеры/асм.c`. Ограничение: операнды используют C-имена переменных как есть
  (переименованные kfc — редкий случай — не подставляются).
- **Структурные литералы** `{…}` → именованные поля Konda `{ поле = знач }`
  (порядок полей берётся из определения `struct`); массивы — позиционно.
- **Цепное присваивание** `a = b = 0` → последовательность операторов справа
  налево; идиома `typedef struct {…} Имя;` — имя typedef переносится на тег.
- **Присваивание и запятая ВНУТРИ выражения** (`f(x = g())`, `a[n = k] = 1`,
  `return (i++, j)`) → присваивание выносится строкой ВЫШЕ оператора, на месте
  остаётся цель; у запятой левые части — отдельные операторы. В выражении Konda
  присваиваний нет, поэтому раньше это давало синтаксически невалидный вывод.
  Где порядок вычисления менять нельзя (`и`/`или`, тернарник, условие цикла) —
  пометка `присваивание-в-выражении`. Пример — `присваивание_в_выражении.c`.
- **NULL** → `нуль`, nullable-указатели → `возможно<T*>` (см. ниже);
  указатель в булевом контексте (`if (p)`, `!p`, `p && …`) → охранник
  `!= нуль`/`== нуль`.
- **Имена функций не трогаются** — ни манглинга, ни транслитерации.

## Пометки: что делать с тем, что не перевелось

Пометка адресована **двум читателям сразу**: человеку — блок-комментарий прямо в
месте проблемы; ИИ/скрипту — те же поля в JSON (`--отчёт`), чтобы раздать задачи
пачкой, не парся исходник. Категория сразу говорит, компилируется ли код:

| категория | компилируется? | смысл |
|---|---|---|
| `НЕПЕРЕВОДИМО` | **нет** | конструкции нет в Konda вовсе (`&x`, `goto`) — нужен ручной редизайн |
| `ОШИБКА` | **нет** | цикл не смог починить; встроена **реальная диагностика транспилятора** — самая действенная пометка |
| `НЕБЕЗОПАСНО` | да, работает | заперто в `небезопасно { }`; можно сузить до безопасной Konda (указатель → `срез<T>`) |
| `ПРОВЕРИТЬ` | да | эвристика могла ошибиться в **смысле** (число элементов в `выделить`, fallthrough в `switch`), либо в исходном C найден баг (double-free) |

Блок легко найти (`grep KONDA-TODO`) и удалить после правки. Каждый несёт
**причину**, **место**, **исходную строку C** и **пронумерованные варианты решения**:

```
// ┌─ KONDA-TODO[НЕПЕРЕВОДИМО] адрес-оф «&»
// │ ПРИЧИНА: в Konda нет оператора «&»: указатель на локальную переменную
// │ недопустим (висячий указатель), мутация делается иначе
// │ ЗДЕСЬ: в инициализаторе объявления
// │ C-ИСХОДНИК: int *p = &x;
// │ ВАРИАНТЫ:
// │   1) если «&x» передаётся в функцию, которая ЗАПИСЫВАЕТ x → объявите
// │      параметр «вывод T x» (C# out) и передайте саму переменную
// │   2) если функция читает И пишет x → параметр «изменяемый T x» (C# ref)
// │   3) если это адрес элемента массива/буфера → передайте «срез<T>» целиком
// │   4) если нужен долгоживущий указатель на кучу → «срез<T> = выделить(N)»
// └─ после исправления удалите этот блок
```

Пометка `ОШИБКА` дополнительно несёт строку `ТРАНСПИЛЯТОР: <текст диагностики>` —
готовое указание на конкретное нарушенное правило безопасности.

### JSON-отчёт для ИИ (`--отчёт задачи.json`)

```json
{ "источник": "файл.c", "флаги_транспилятора": ["-I/путь/к/каталогу/.c"],
  "всего": 2, "блокирует_компиляцию": 2,
  "по_категориям": {"НЕПЕРЕВОДИМО": 1, "ОШИБКА": 1, "НЕБЕЗОПАСНО": 0, "ПРОВЕРИТЬ": 0},
  "задачи": [{ "файл": "…", "строка": 7, "категория": "НЕПЕРЕВОДИМО",
               "код": "адрес-оф", "причина": "…", "деталь": "в инициализаторе…",
               "c_исходник": "int *p = &x;", "диагностика": null,
               "варианты": ["…"], "блокирует_компиляцию": true }] }
```

Поле `код` группирует однотипные задачи (`адрес-оф`, `goto`, `выделить-счёт`,
`switch-провал`, …) — удобно раздавать ИИ пачками одного вида. Сортировка по
`блокирует_компиляцию` даёт естественный порядок работ.

### Что именно не выразимо в Konda

- **Адрес-оф `&x`** остаётся пометкой в трёх случаях: вариативные функции
  (`scanf("%d", &x)` — сигнатуру не типизировать), `&массив[i]` (нужен подсрез
  на стороне языка) и указатель, живущий своей жизнью (переприсваивание/
  арифметика). Вызовы функций проекта, ПЕРЕСЫЛКА указателя вглубь и вызовы
  библиотек с `&x` (через `внешняя`-прототипы) переводятся автоматически.
- **`goto` из вложенных циклов** → помеченные `прервать`/`продолжить` (§122,
  см. «Что уже переводится»).
- **`goto` cleanup → функция «goto_<имя>» + ранний возврат.** Самый частый
  паттерн (16 из 17 функций weston с goto): ОДНА метка в хвосте функции, все
  `goto` ведут в неё, перед меткой — `return` (нет проваливания), хвост
  завершается `return`. kfc **выносит хвост-метку в отдельную функцию
  `goto_<имя_функции>`** (её параметры — те, что использует cleanup, с тем же
  режимом `изменяемый`/`вывод`/`возможно`), а каждый `goto` заменяет на
  `вернуть goto_<имя>(…)`. Автоosвобождение срезов срабатывает на этом раннем
  возврате, поэтому cleanup-хвост обычно сводится к вызовам + return-коду. Не
  выносятся (остаются пометкой `goto`): хвост использует ЛОКАЛЬ функции (нужна
  передача состояния), несколько меток (вложенный `err0/err1`), проваливание в
  метку (перед ней не `return`). Прочий `goto` (машины состояний, прыжки вверх)
  — нет by design (конфликт с владением/definite-assignment); переписать
  циклом/условием.
- Пока не переводятся: битовые поля, вариативные **определения** функций,
  `typedef`-псевдонимы простых типов ИЗ ФАЙЛА ПРОЕКТА (пометка `typedef-алиас`;
  typedef-ы заголовков разворачиваются, см. выше).
- **Безымянные `union`/`struct`-члены структуры** (C11, напр. weston-матрицы
  `struct { union { float el[4]; struct { float x,y,z,w; }; }; }`) —
  **переводятся**: у члена и у типа в Konda должно быть имя, поэтому kfc
  поднимает запись как `Внешняя_анонN` (`союз`/`структура`, вложенные — раньше
  внешней, прямо перед ней) с членом `_анонN`, а доступ `v.x` печатает как
  `v._анон0._анон0.x` (член союза — под `небезопасно`, как любой type punning).
  Примеры — `аноним_союз.c`, `аноним_член.c` (вывод совпадает с C).

> **Побитовые операции** `& | ^ << >> ~` теперь **поддерживаются** языком Konda
> (целочисленные, нулевая цена) — kfc переводит их напрямую, без пометок.

## Можно ли так перевести «очень много кода» из C в Konda без ИИ?

Коротко: **синтаксически — да, для больших объёмов; но «готовый безопасный
Konda» — нет, и это не про качество конвертера, а про замысел Konda.**

1. **Механический перевод масштабируется — и уже работает.** clang разбирает любой
   валидный C-файл целиком и точно. kfc покрывает бо́льшую часть грамматики
   (struct/enum/union, switch, тернарник, casts, malloc→срез, сырые указатели в
   `небезопасно`) и на выходе даёт `.конда`, который **проходит транспилятор и
   запускается** (см. `тесты/прогон.sh`). Это масштабируется на тысячи файлов
   пакетно, без ИИ. Ограничивают не столько «непокрытые» узлы, сколько
   конструкции, которых в Konda нет вовсе (`&x`, `goto`).

2. **Но Konda НАМЕРЕННО отвергает идиоматичный небезопасный C.** Сырые указатели
   и адресная арифметика, `&локальная`, ручной `malloc/free`, каламбур типов
   через `union`, `T*`, который может быть `NULL`, — всё это в Konda либо
   запрещено, либо требует `небезопасно { }`, `возможно<T*>`, `срез`,
   `изменяемый/вывод` вместо `&`. Никакой фронтенд не превратит произвольный C в
   код, который пройдёт эти проверки: **нужное знание (кто чем владеет, что может
   быть null, где границы) в C-исходнике просто отсутствует.**

3. **Практический итог.** Реалистичный конвейер — *двухшаговый*:
   `kfc` даёт синтаксически верный черновик → `Транспилятор` его проверяет и
   выдаёт список мест, требующих ручного решения по безопасности. Чем «чище» и
   современнее исходный C (мало сырых указателей, простое владение), тем меньше
   ручных правок. Для низкоуровневого системного C правок будет много.

   Массовость достижима на **шаге 1** (перевести и скомпилировать много кода) и на
   **триаже** (транспилятор автоматически показывает, что осталось). Полностью
   автоматической «безопасной» миграции произвольного проекта без участия человека
   — не будет by design; здесь и мог бы помогать ИИ (предлагать владение/nullable),
   но это уже за рамками детерминированного конвертера.

4. **Замер на реальном корпусе** (`тесты/корпус.sh`, 40 клиентов weston).
   Все 40 файлов kfc переводит, но ни один пока не проходит транспилятор
   целиком. Главные оставшиеся блокеры: адрес-оф `&x`, сохраняемый в поля
   (Vulkan `pNext`, create-info, таблицы опций — предел языка), пределы
   ёмкости самого транспилятора (Vulkan, `window.c`), enum-константы и внешние
   переменные C-заголовков, несовпадение сигнатур колбэков в
   listener-таблицах.

## Структура

- `kfc.py` — конвертер (stdlib-only): вызов clang, обход JSON-AST, эмиссия,
  многофайловый драйвер (`Единица`/`конвертировать_проект`), политика
  ослабления и цикл проверки.
- `владение.py` — эвристика владения: `T *p` + `f(&x)` → `изменяемый`/`вывод`,
  транзитивное распространение по графу вызовов (фикспоинт).
- `нулевые.py` — NULL-анализ: какие указатели бывают `нуль` → `возможно<T*>`.
- `проверка.py` — запуск транспилятора подпроцессом, разбор диагностик,
  таблица «текст ошибки → действие».

## Ограничения (в силу замысла Konda, не конвертера)

Не выразимо и остаётся пометкой до ручной доработки: **адрес-оф `&x`** и **`goto`**.
Это язык Konda таков по дизайну (безопасность памяти), а не пробел kfc. Побитовые
операции `& | ^ << >> ~` — уже поддерживаются, переводятся напрямую.

**Тело колбэка с `void *data` — фундаментально не типизируется.** Идиома
`static void cb(void *data, …) { struct T *p = data; … }` запирается в
`небезопасно` (сырой `void*`→`T*` без проверки). Ретипизировать параметр в
`изменяемый T` НЕЛЬЗЯ: сигнатура колбэка зафиксирована контрактом
указателя-на-функцию в listener-структуре (`void (*)(void*, …)`), и смена
первого параметра сломала бы присваивание `{ .release = cb }` (несовместимые
указатели на функции). Разблокировать это можно только языковой фичей
«доверенный `void*` → `T`» — вне охвата конвертера. Поэтому такие тела (и всё
транзитивно от них: локальные `T *p = data` и функции, куда `p` уходит) остаются
`небезопасно`. **Регистрация** самого колбэка при этом переводится (см. выше —
`типфункции`-параметр и типизация `void *data` у `add_listener`). Исключение —
слушатели из системных заголовков: их kfc переводит в `внешний слушатель<T>`
(§13/§68 языка), и каст `void*→T` уходит в доверенный трампулин транспилятора
(см. «Стратегия безопасности»).
