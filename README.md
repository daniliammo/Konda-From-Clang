# konda-from-clang (kfc)

Конвертер **C → Konda** через AST-дамп компилятора **clang**. Отдельный проект,
не зависит от `libkonda` и не линкует `libclang` — общение с clang только через
внешний процесс (`clang -Xclang -ast-dump=json`).

```
файл.c ──clang -ast-dump=json──▶ JSON-AST ──kfc.py──▶ файл.конда ──▶ .c ──▶ .elf
                                              ▲            │
                                              │            ▼
                                        уточнить    транспилятор Konda
                                        политику ◀── диагностики (цикл проверки)
```

kfc **только переводит синтаксис**. Никаких проверок памяти/типов он не делает —
по инварианту экосистемы Konda все проверки безопасности живут в транспиляторе.
Поэтому результат kfc — это черновик `.конда`, который затем прогоняется через
`Транспилятор`; тот и укажет, где перевод небезопасен и требует ручной правки.

## Почему через `clang -ast-dump=json`, а не рукописный парсер

Прежний конвертер (`СиВКонда` в основном репозитории) — рукописный парсер C.
Он никогда не догонит реальный C: препроцессор, все объявители, точные типы,
разрешение имён. clang уже всё это делает и отдаёт **готовое, типизированное,
препроцессированное** дерево. Мы берём его как есть.

- **Без линковки.** clang вызывается как процесс, JSON читается из stdout.
  Обновление clang не ломает сборку (нет ABI-зависимости от libclang).
- **Верные типы.** В JSON у каждого узла есть `type.qualType` — точный тип после
  разрешения `typedef`, `sizeof`, промоушенов.
- **Препроцессор бесплатно.** `#include`, `#define`, `#if` уже раскрыты. Минус —
  раскрыты *насовсем*: исходные `#if`-ветки в вывод не попадают (см. ниже).

## Запуск

```sh
python3 kfc.py примеры/demo.c                 # печать .конда в stdout
python3 kfc.py примеры/demo.c -o out.конда    # запись в файл
python3 kfc.py файл.c --отчёт задачи.json     # + машиночитаемый список задач
python3 kfc.py файл.c --без-проверки          # выключить цикл проверки
python3 kfc.py файл.c --итераций 10           # предел итераций цикла (по умолч. 6)
python3 kfc.py файл.c --транспилятор ПУТЬ     # где взять транспилятор Konda
python3 kfc.py файл.c -- -I../include -DDEBUG # флаги после -- уходят clang'у
```

Требуется `clang` в `PATH` и `python3` (только стандартная библиотека). Для цикла
проверки нужен бинарник транспилятора Konda: ищется по `--транспилятор`, затем
`$KONDA_ТРАНСПИЛЯТОР`, затем у соседа `../Транспилятор/Собранное/Транспилятор`,
затем в `PATH`. Без него цикл молча выключается (перевод остаётся эвристическим).

## Цикл проверки: «сгенерировал → проверил транспилятором → уточнил»

kfc не угадывает, где нужна небезопасность, — он **спрашивает транспилятор**.
Тот собирает семантические ошибки ПАЧКОЙ за прогон, поэтому цикл сходится за
2-3 итерации. Транспилятор запускается ПОДПРОЦЕССОМ (libkonda не линкуется —
по инварианту экосистемы; узкое место всё равно clang, а не запуск процесса).

Лестница ослабления для каждого места — ослабляем строго по факту возражения:

| шаг | что делаем | когда |
|---|---|---|
| 1 | безопасный перевод (`срез`/массив) | по умолчанию |
| 2 | параметр `T*` → **`изменяемый`/`вывод`** | «выходной параметр не присвоен» → ref; «изменяемый-аргумент не инициализирован» → out |
| 2 | параметр `T*` → **`срез<T>`** | «…теряет длину: объявите как срез<T>» |
| 3 | `небезопасно { оператор }` | «индексация сырого указателя», «арифметика указателей», reinterpret, доступ к союзу |
| 4 | `небезопасно { }` на всё тело функции | переменная ушла из области («неизвестная переменная») |
| 5 | пометка `KONDA-TODO` | ничего из перечисленного не помогло |

Пример выигрыша (`примеры/цикл_проверки.c`): у функции `обёртка` параметр не
индексируется в теле, поэтому статическая эвристика оставляет сырой указатель —
и такой код транспилятор бы отверг. Цикл видит ошибку на вызове и сам поднимает
параметр до `срез<целое32>`:

```
--без-проверки → целое32 обёртка(целое32* a, целое32 n)      // отвергается
с циклом       → целое32 обёртка(срез<целое32> a, целое32 n) // принят, 0 пометок
```

В конце kfc печатает вердикт: `итог: принят транспилятором (итераций цикла: 2);
пометок: 0` — то есть перевод **доказанно** проходит транспилятор, а не «наверное».

## Эвристика владения: `f(&x)` → `изменяемый` / `вывод`

В Konda нет оператора `&` — мутация переменной вызывающего выражается
**модификатором параметра**, а `&`/`*` расставляет кодоген. Раньше каждый
`f(&x)` был блокирующей пометкой; теперь `владение.py` выводит это сам.

Для каждой функции, **определённой в файле**, смотрим на её указательные
параметры и на все вызовы в файле:

| в теле функции | все вызовы дают `&переменная`? | результат |
|---|---|---|
| только пишет `*p = …` | да | **`вывод T p`** (C# out) |
| читает и/или пишет `*p`, `p[0]`, `p->поле` | да | **`изменяемый T p`** (C# ref) |
| индексирует `p[i]`, i≠0 | — | `срез<T>` (другой путь) |
| арифметика `p+n`, `p++`, переприсваивание | — | сырой указатель |
| передаёт `p` дальше как указатель | — | не трогаем (чужая сигнатура) |
| хоть один вызов даёт не `&переменная` | нет | не трогаем |

В теле `*p`/`p[0]` печатаются просто как `p`, на вызове `&x` → `x`. Внешние
функции (`scanf` и пр.) не трогаем — их сигнатуру менять нельзя.

Догадку «вывод vs изменяемый» **проверяет и правит цикл**: транспилятор точно
скажет `выходной параметр «p» не присвоен до возврата` (→ переключаем на
`изменяемый`) или `«изменяемый»-аргумент «x» должен быть инициализирован`
(→ пробуем `вывод`); если не подошло ни то, ни другое — откат к указателю.

### Локальный указатель-алиас: `T *p = &x;` → подстановка

Локальный указатель на переменную — это просто **другое имя** для неё. kfc
подставляет `x` вместо `p` и вовсе опускает объявление (`примеры/локальный_указатель.c`):

```c
int x = 5;  int *p = &x;      →   целое32 x = 5
printf("%d", p[0]);  *p = 10; →   printf("%d", x)   x = 10
Точка *ук = &т; ук->x += 100; →   т.x = т.x + 100
```

Условие безопасности: **каждое** упоминание `p` — разыменование (`*p`, `p[0]`,
`p->поле`). Любое другое использование (переприсваивание `p = …`, арифметика
`p + 1`, передача `f(p)`, `вернуть p`) значит, что указатель живёт своей жизнью —
тогда не подставляем. Цели с индексом (`&массив[и]`) тоже исключены: `и` мог бы
измениться между объявлением и использованием, и подстановка изменила бы смысл.

Результат (`примеры/владение.c`) — пять типовых C-паттернов мутации переводятся
**полностью автоматически, 0 пометок**, и вывод совпадает с оригинальным C:

```c
void заполнить(int *р)      { *р = 42; }        →  ничего заполнить(вывод целое32 р)
void удвоить(int *з)        { *з = *з * 2; }    →  ничего удвоить(изменяемый целое32 з)
void сдвинуть(Точка *т,…)   { т->x = …; }       →  ничего сдвинуть(изменяемый Точка т, …)
заполнить(&r); удвоить(&v); сдвинуть(&т, 10);   →  заполнить(r) удвоить(v) сдвинуть(т, 10)
```

## Стратегия безопасности: минимум «небезопасно», честные пометки

Цель — чтобы вывод **прошёл транспилятор и работал как задумано**. Правила
(выведены эмпирически из транспилятора):

- **Массив/срез индексируются безопасно** (проверка границ) — `небезопасно` не
  нужно. **Сырой указатель** (индекс `p[i]`, разыменование `*p`, арифметика
  `p + n`, reinterpret-cast `(T*)x`, доступ к члену `union`) требует
  `небезопасно { }` — kfc оборачивает **минимально**, только задетые операторы.
- **Указательный параметр `T*`, который в теле индексируется** и не участвует в
  арифметике, переводится в **`срез<T>`** — тогда индексация внутри безопасна, а
  длина сохраняется. Массив на вызове передаётся в такой параметр напрямую.
- **`malloc`/`calloc` → `срез<T> p = выделить(N)`**, последующие `p[i]` безопасны,
  а `free(p)` **отбрасывается** (у среза автоосвобождение). Число элементов
  извлекается из `N*sizeof(T)` / `calloc(N,…)`; если неоднозначно — пометка.
- Если сырой указатель **объявляется с небезопасным инициализатором** (арифметика/
  reinterpret) и живёт дальше по коду, statement-обёртка невозможна (переменная
  ушла бы из области) — тогда **тело функции целиком** оборачивается в
  `небезопасно { }` (+ пометка, чтобы позже сузить/перевести в `срез`).
- Избыточное `небезопасно` безвредно (обычный C-блок, нулевая цена) — поэтому в
  спорных местах kfc оборачивает консервативно, гарантируя проход.

## Что уже переводится

- Функции, параметры, тело; `main` → `точка_входа` (соглашение языка).
- **Типы**: примитивы C → Konda (`int`→`целое32`, `char`→`символ`,
  `double`→`вещественное64`, `unsigned` → префикс `неподписанный`, `void*` →
  `символ*`), указатели суффиксом `*`; **`struct`/`union`/`enum`** →
  `структура`/`союз`/`перечисление`; typedef указателя на функцию → `типфункции`.
- **Операторы**: `если/иначе` (цепочки как вложенные `иначе { если … }`), `пока`,
  `для`, `do-while` → `пока (истина){… если(!усл){прервать}}`, `вернуть`,
  `прервать`, `продолжить`. **`switch` → цепочка `если/иначе если`** (Konda-`выбор`
  только для enum/sum-типов; `case A: case B:` → `x == A или x == B`; `break`
  отбрасывается; проваливание — помечается).
- **Выражения**: бинарные (`&&`/`||` → `и`/`или`), присваивания, `+=`/… → `a=a+b`,
  `++`/`--` → `x=x+1`, вызовы, индексация, поле `.`/`->` → `.`, каст → `как<T>(…)`,
  `sizeof` → `размер_обьекта(…)`, **тернарник** `?:` понижается в `если/иначе`
  (в объявлении, `return`, присваивании). Строки с кириллицей раскодируются из
  октальных escape'ов в UTF-8. `printf` — как есть.
- **Структурные литералы** `{…}` → именованные поля Konda `{ поле = знач }`
  (порядок полей берётся из определения `struct`); массивы — позиционно.
- **Имена функций не трогаются** — ни манглинга, ни транслитерации.

## Пометки: что делать с тем, что не перевелось

Пометка адресована **двум читателям сразу**: человеку — блок-комментарий прямо в
месте проблемы; ИИ/скрипту — те же поля в JSON (`--отчёт`), чтобы раздать задачи
пачкой, не парся исходник. Категория сразу говорит, компилируется ли код:

| категория | компилируется? | смысл |
|---|---|---|
| `НЕПЕРЕВОДИМО` | **нет** | конструкции нет в Konda вовсе (`&x`, `goto`) — нужен ручной редизайн |
| `ОШИБКА` | **нет** | цикл не смог починить; встроена **реальная диагностика транспилятора** — самая действенная пометка |
| `НЕБЕЗОПАСНО` | да, работает | заперто в `небезопасно { }`; можно сузить до безопасной Konda (указатель → `срез<T>`) |
| `ПРОВЕРИТЬ` | да | эвристика могла ошибиться в **смысле** (число элементов в `выделить`, fallthrough в `switch`) |

Блок легко найти (`grep KONDA-TODO`) и удалить после правки. Каждый несёт
**причину**, **место**, **исходную строку C** и **пронумерованные варианты решения**:

```
// ┌─ KONDA-TODO[НЕПЕРЕВОДИМО] адрес-оф «&»
// │ ПРИЧИНА: в Konda нет оператора «&»: указатель на локальную переменную
// │ недопустим (висячий указатель), мутация делается иначе
// │ ЗДЕСЬ: в инициализаторе объявления
// │ C-ИСХОДНИК: int *p = &x;
// │ ВАРИАНТЫ:
// │   1) если «&x» передаётся в функцию, которая ЗАПИСЫВАЕТ x → объявите
// │      параметр «вывод T x» (C# out) и передайте саму переменную
// │   2) если функция читает И пишет x → параметр «изменяемый T x» (C# ref)
// │   3) если это адрес элемента массива/буфера → передайте «срез<T>» целиком
// │   4) если нужен долгоживущий указатель на кучу → «срез<T> = выделить(N)»
// └─ после исправления удалите этот блок
```

Пометка `ОШИБКА` дополнительно несёт строку `ТРАНСПИЛЯТОР: <текст диагностики>` —
готовое указание на конкретное нарушенное правило безопасности.

### JSON-отчёт для ИИ (`--отчёт задачи.json`)

```json
{ "источник": "файл.c", "всего": 2, "блокирует_компиляцию": 2,
  "по_категориям": {"НЕПЕРЕВОДИМО": 1, "ОШИБКА": 1, "НЕБЕЗОПАСНО": 0, "ПРОВЕРИТЬ": 0},
  "задачи": [{ "файл": "…", "строка": 7, "категория": "НЕПЕРЕВОДИМО",
               "код": "адрес-оф", "причина": "…", "деталь": "в инициализаторе…",
               "c_исходник": "int *p = &x;", "диагностика": null,
               "варианты": ["…"], "блокирует_компиляцию": true }] }
```

Поле `код` группирует однотипные задачи (`адрес-оф`, `goto`, `выделить-счёт`,
`switch-провал`, …) — удобно раздавать ИИ пачками одного вида. Сортировка по
`блокирует_компиляцию` даёт естественный порядок работ.

### Что именно не выразимо в Konda

- **Адрес-оф `&x` в вызове ВНЕШНЕЙ функции** — `scanf("%d", &x)` и т.п.: её
  сигнатуру менять нельзя, а `&` в Konda нет даже в `небезопасно`. Автоматического
  перевода не существует в принципе. Вызовы функций **этого файла** и локальные
  алиасы переводятся автоматически (см. выше), остаётся `&массив[i]` и указатель,
  живущий своей жизнью (переприсваивание/арифметика).
- **`goto`/метки** — нет by design (конфликт с владением/деструкторами/
  definite-assignment); переписать циклом/условием. «goto cleanup» не нужен —
  срезы autofree сами освобождаются при выходе из области.
- Пока не переводятся: `typedef`-псевдонимы простых типов (в Konda нет алиасов —
  пометка с заменой), анонимные `enum`, битовые поля, вариативные **определения**
  функций, объединение нескольких `.c` (пока файл за файлом).

> **Побитовые операции** `& | ^ << >> ~` теперь **поддерживаются** языком Konda
> (целочисленные, нулевая цена) — kfc переводит их напрямую, без пометок.

## Можно ли так перевести «очень много кода» из C в Konda без ИИ?

Коротко: **синтаксически — да, для больших объёмов; но «готовый безопасный
Konda» — нет, и это не про качество конвертера, а про замысел Konda.**

1. **Механический перевод масштабируется — и уже работает.** clang разбирает любой
   валидный C-файл целиком и точно. kfc покрывает бо́льшую часть грамматики
   (struct/enum/union, switch, тернарник, casts, malloc→срез, сырые указатели в
   `небезопасно`) и на выходе даёт `.конда`, который **проходит транспилятор и
   запускается** (см. `тесты/прогон.sh`). Это масштабируется на тысячи файлов
   пакетно, без ИИ. Ограничивают не столько «непокрытые» узлы, сколько
   конструкции, которых в Konda нет вовсе (`&x`, `goto`).

2. **Но Konda НАМЕРЕННО отвергает идиоматичный небезопасный C.** Сырые указатели
   и адресная арифметика, `&локальная`, ручной `malloc/free`, каламбур типов
   через `union`, `T*`, который может быть `NULL`, — всё это в Konda либо
   запрещено, либо требует `небезопасно { }`, `возможно<T*>`, `срез`,
   `изменяемый/вывод` вместо `&`. Никакой фронтенд не превратит произвольный C в
   код, который пройдёт эти проверки: **нужное знание (кто чем владеет, что может
   быть null, где границы) в C-исходнике просто отсутствует.**

3. **Практический итог.** Реалистичный конвейер — *двухшаговый*:
   `kfc` даёт синтаксически верный черновик → `Транспилятор` его проверяет и
   выдаёт список мест, требующих ручного решения по безопасности. Чем «чище» и
   современнее исходный C (мало сырых указателей, простое владение), тем меньше
   ручных правок. Для низкоуровневого системного C правок будет много.

   Массовость достижима на **шаге 1** (перевести и скомпилировать много кода) и на
   **триаже** (транспилятор автоматически показывает, что осталось). Полностью
   автоматической «безопасной» миграции произвольного проекта без участия человека
   — не будет by design; здесь и мог бы помогать ИИ (предлагать владение/nullable),
   но это уже за рамками детерминированного конвертера.

## Структура

- `kfc.py` — конвертер (stdlib-only): вызов clang, обход JSON-AST, эмиссия,
  политика ослабления и драйвер цикла проверки.
- `владение.py` — эвристика владения: `T *p` + `f(&x)` → `изменяемый`/`вывод`.
- `проверка.py` — запуск транспилятора подпроцессом, разбор диагностик,
  таблица «текст ошибки → действие».
- `пометки.py` — категории, рецепты (причина + варианты решения), JSON-отчёт.
- `примеры/` — `demo.c` (управление), `богатый.c` (struct/enum/switch/malloc/
  тернарник), `указатели.c` (сырые указатели/срез-параметр/union/reinterpret),
  `цикл_проверки.c` (цикл чинит то, что эвристика пропустила),
  `владение.c` (`f(&x)` → `изменяемый`/`вывод`, 0 пометок),
  `локальный_указатель.c` (`T *p = &x` → подстановка, 0 пометок),
  `непереводимое.c` (`scanf("%d", &x)` — предел языка → пометка).
- `тесты/прогон.sh` — сквозной smoke-тест: каждый пример C → `.конда` → (если
  рядом транспилятор) `.c` → `.elf` и проверка вывода.

## Дорожная карта (следующее)

1. **Сузить `небезопасно`**: где тело обёрнуто целиком из-за сырого указателя —
   попытаться перевести указатель в `срез<T>` (по образцу параметров), убрав
   обёртку; цикл проверки подтвердит или откатит попытку.
2. **Многофайловость** по `compile_commands.json` — сейчас файл за файлом.
3. **Многофайловость** по `compile_commands.json`; `#include` проекта.
4. `Результат<T,E>`/nullable: `T*`, сравниваемый с `NULL`, → `возможно<T*>`
   с разворотом под охранником (устранит часть `небезопасно`).
5. Точный `размер_обьекта` и число элементов в `выделить` для сложных выражений.

## Ограничения (в силу замысла Konda, не конвертера)

Не выразимо и остаётся пометкой до ручной доработки: **адрес-оф `&x`** и **`goto`**.
Это язык Konda таков по дизайну (безопасность памяти), а не пробел kfc. Побитовые
операции `& | ^ << >> ~` — уже поддерживаются, переводятся напрямую.
